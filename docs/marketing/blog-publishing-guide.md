# Публикуване в Bricky блога

## Текущо състояние

- Публичен адрес: https://bricky.bg/blog
- Връзка „Блог“ в desktop и mobile менюто.
- Само записи със `status: 'published'` са видими в списъка, категориите, препоръките и директните адреси.
- Демонстрационните материали не се публикуват.
- Няма CMS или редактор за блог в админ панела. Съдържанието се добавя през кода и изисква frontend build и deployment.
- Този релийз не публикува статии от маркетинговия план, който не е предоставен тук.

## Какво да подготвиш

За всяка статия: заглавие, кратко резюме, категория, основен текст с подзаглавия, автор и собствена или лицензирана снимка с описание. По желание: чести въпроси и връзки към свързани статии. Не използваме измислени отзиви, непроверени цени и чужди снимки без права.

Можеш да дадеш текста като Markdown или Word документ. След редакционното ти одобрение го оформяме в структурата по-долу и публикуваме.

## Структура в кода

Файл: `frontend/src/data/blogContent.js`. Добави обект в `editorialBlogArticles`:

```js
{
  id: 'unique-article-id',
  slug: 'kratak-adres-na-latinica',
  status: 'draft',
  title: 'Заглавие на статията',
  excerpt: 'Кратко и конкретно резюме.',
  categoryKey: 'choose-worker',
  categoryLabel: 'Избор на майстор',
  coverImage: '/assets/blog/unique-article-cover.webp',
  coverAlt: 'Описание на видимото в снимката',
  readingTimeMinutes: 4,
  authorName: 'Екипът на Bricky',
  featured: false,
  metaTitle: 'Заглавие на статията | Bricky',
  metaDescription: 'Кратко описание за търсачките.',
  sections: [
    {
      id: 'podgotovka',
      heading: 'Подготовка',
      paragraphs: ['Първи абзац.', 'Втори абзац.'],
      bullets: ['Първа точка', 'Втора точка'],
    },
  ],
  faq: [],
  relatedSlugs: [],
}
```

Категории: `bathroom-plumbing`, `walls-painting`, `electrical`, `flooring`, `roofing`, `full-renovation`, `choose-worker`.

Снимките се добавят във `frontend/public/assets/blog/`. Текстът е структуриран, не произволен HTML. Не слагай поверителни чернови или лични данни в този файл: това е frontend код, а не защитено хранилище за редактори.

## Публикуване

1. Преглед и одобрение на текста и правата за снимките.
2. `status: 'published'`; уникален slug; при нужда `featured: true` за една водеща статия.
3. Добавяне на адреса `https://bricky.bg/blog/<slug>` във `frontend/public/sitemap.xml`.
4. `node --test scripts/verify-blog-publishing.mjs` и `npm run build` във frontend.
5. Backup на работещия frontend, контролирано качване и проверка на desktop/mobile.
6. Проверка на заглавието, canonical, `index,follow`, снимките и връзките.

Няма автоматично публикуване по дата. Няма обещание за незабавно индексиране. Текущата платформа е React SPA: основният текст и meta данните се визуализират с JavaScript. За по-надеждни социални previews и SEO следваща отделна задача е предварително рендериране на статиите, а не промяна на дизайна на целия сайт.

## Оттегляне

Смени статуса на `draft`, премахни адреса от sitemap и направи нов build/deployment. Непубликуваният адрес показва „Статията не е намерена“ с `noindex`. Засега SPA fallback връща HTTP 200 и за този екран; истински HTTP 404 е част от бъдещото предварително рендериране/сървърно маршрутизиране.
