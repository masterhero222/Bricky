# Публикуване в Bricky блога

## Организация

- Блог: https://bricky.bg/blog
- Рубрика: https://bricky.bg/blog?rubrika=kolko-struva
- Първа статия: https://bricky.bg/blog/kolko-struva-remont-na-banya-2026
- Всяка рубрика събира много статии. Всяка статия има един основен раздел и собствен постоянен адрес.
- Рубриките са отделни от професиите и категориите на калкулатора.
- Списъкът е в `frontend/src/data/blogRubrics.js`: Колко струва, Червен флаг при ремонт, Брики обяснява, Истински обекти, Ремонтни дилеми, За професионалисти, Строим Bricky.
- Празните рубрики са достъпни през менюто, но не се повтарят като празни секции на общата страница. Имат `noindex,follow`, докато няма материал.

## Добавяне на статия

Добави Markdown файл във `frontend/content/blog/`. Поддържат се подзаглавия, списъци, удебеляване, таблици и линкове. Пример за началните метаданни:

```yaml
---
title: "Заглавие на статията"
slug: "unikalen-adres-na-latinica"
description: "Кратко описание за списъка и търсачките."
category: "Колко струва"
status: "draft"
author: "Екипът на Bricky"
reading_time: "5 минути"
published_at: "2026-08-30"
updated_at: "2026-08-30"
cover: "/assets/worker-banners/v1/blueprint-bathroom.webp"
cover_alt: "Техническа илюстрация на баня"
calculator_category: "bathroom_renovation"
---
```

След метаданните следва текстът. Незадължително първо H1 заглавие трябва да съвпада с `title`; то се показва веднъж. H2 подзаглавията автоматично създават съдържание с връзки към секциите.

Снимките са собствени или лицензирани и се добавят в `frontend/public/assets/`. Не се използват клиентски снимки без разрешение. Редакторът проверява цените, източниците и твърденията преди публикуване; техническият build не удостоверява тяхната достоверност.

## Публикуване

1. Одобри текста и смени `status` на `published`. Без статус материалът е чернова.
2. Задай валидна дата на публикуване и актуализация. Датите не са автоматичен график.
3. Добави адреса на статията и `lastmod` във `frontend/public/sitemap.xml`. Добави адреса на рубриката при първата й публикация.
4. Във frontend изпълни `npm run test:blog` и `npm run build`.
5. Направи backup на live frontend, качи проверения build и провери статията на телефон и компютър.

`npm run content:blog` генерира `src/data/blogContent.generated.json`. Същата стъпка се изпълнява автоматично преди build и преди `npm run dev`. След редактиране на Markdown при вече работещ dev server я изпълни отново. Не редактирай генерирания JSON ръчно.

Build-ът спира при неизвестна рубрика, невалиден slug, дублиран адрес, липсваща корица или липсваща дата на публикуван материал. Само публикуваните материали влизат в генерирания каталог. Черновите не се изпращат към браузъра, но са в Git: не съхранявай поверителна информация в тях.

## Оттегляне

Смени статуса на `draft`, премахни адреса от sitemap и направи нов build/deployment. При оттегляне на последната статия в рубрика премахни и рубриката от sitemap. Директният адрес показва „Статията не е намерена“.

## Ограничения

Няма редактор за блог в админ панела, база за съдържание или автоматично публикуване по дата. Засега статиите се публикуват през кода и deployment.

Платформата остава React SPA: текстът, canonical, meta данните и BlogPosting JSON-LD се визуализират с JavaScript. Социалните previews и сървърно индексиране изискват отделна задача за предварително рендериране. Непознатите адреси все още получават HTTP 200 от SPA fallback, но показват not-found екран с `noindex`.
